# 요구사항 정리 (초안)

이 문서는 Open Screen Reader의 요구사항을 정리하고, 첫 번째 목표(MVP)의 범위를 정하기 위한 문서입니다.
내용은 계속 바뀔 수 있으며, 시각장애인 사용자와 기여자의 의견을 받아 수정합니다.

## 1. 전체 비전 (장기 목표)

- Windows와 macOS에서 동작하는 무료 화면 읽기 프로그램
- 화면의 글자, 컨트롤, 그림 정보를 음성과 점자로 전달
- 화면 내용을 정확히 살펴보는 리뷰 기능
- 복잡한 그래픽을 주요 특징 중심으로 해설
- 기본 인터페이스로 쓰기 어려운 프로그램을 위한 별도 접근성 인터페이스
- 높은 안정성과 빠른 음성 응답

## 2. MVP 범위 (첫 번째 목표)

한 줄 요약: **Windows 10/11에서 포커스가 바뀔 때 그 내용을 음성으로 읽고, 키보드로 화면을 탐색(리뷰)할 수 있다.**

### MVP에 포함

| 번호 | 기능 | 설명 |
| --- | --- | --- |
| M1 | 포커스 추적 | 키보드 포커스가 이동하면 해당 요소의 이름, 역할, 상태를 읽습니다. |
| M2 | 음성 출력 | 시스템 TTS로 음성을 출력합니다. 속도, 음량, 음성 선택을 조절할 수 있습니다. |
| M3 | 음성 중단과 대기열 | 새 포커스 이동 시 이전 음성을 즉시 끊고 새 내용을 읽습니다. 사용자가 단축키로 음성을 멈출 수 있습니다. |
| M4 | 텍스트 입력 피드백 | 입력한 글자와 단어, 커서 이동 시 해당 줄과 글자를 읽습니다. |
| M5 | 기본 리뷰 | 현재 창의 내용을 개체, 줄, 단어, 글자 단위로 이전/다음 이동하며 읽습니다. |
| M6 | 전용 단축키 | 화면 읽기 프로그램 전용 키(수정 키)를 두고, 기본 단축키를 제공합니다. |
| M7 | 시작과 종료 | 로그인 후 자동 실행 옵션, 단축키로 종료, 실행 상태 음성 안내를 제공합니다. |
| M8 | 설정 | 접근성을 갖춘 설정 화면(키보드만으로 조작 가능)에서 음성과 단축키를 바꿉니다. |

### MVP에서 제외 (이후 단계)

- macOS 지원
- 점자 출력
- 그래픽/이미지 해설
- 별도 전용 인터페이스(앱별 보조 UI)
- Windows 10 미만 구형 OS 지원

## 3. 이후 단계 후보

| 단계 | 내용 |
| --- | --- |
| 2단계 | 웹 브라우저(크롬, 엣지) 지원 강화, 문서 읽기(연속 읽기, 제목/링크 이동) |
| 3단계 | 점자 정보 단말기 지원 |
| 4단계 | macOS 지원 |
| 5단계 | 이미지와 그래픽 해설(OCR, 이미지 설명) |
| 6단계 | 앱별 전용 인터페이스 |

## 4. 비기능 요구사항

- **응답 속도**: 포커스 이동에서 음성 시작까지의 지연을 측정 가능한 목표로 관리합니다. 목표값은 프로토타입에서 측정한 뒤 정합니다.
- **안정성**: 화면 읽기 프로그램이 멈추거나 오류가 나도 사용자의 컴퓨터 사용을 막지 않아야 합니다. 비정상 종료 시 자동 재시작과 오류 로그를 둡니다.
- **자원 사용**: 메모리와 CPU 사용량이 작아야 합니다.
- **접근성**: 프로그램 자체의 모든 화면과 설치 과정을 키보드와 다른 화면 읽기 프로그램으로 조작할 수 있어야 합니다.
- **개인정보**: 화면 내용과 입력 내용(비밀번호 포함)을 외부로 전송하지 않습니다. 비밀번호 입력란은 내용을 읽지 않습니다.
- **설치**: 설치 과정 자체가 화면 읽기 프로그램 없이도 시작할 수 있도록, 휴대용(포터블) 실행도 검토합니다.

## 5. 구형 Windows 지원에 대한 메모

기획 단계의 요구사항에는 Windows 98, ME, 2000, XP, 7 지원이 있었습니다. 그러나 다음 이유로 MVP에서는 제외하고, 이후에 별도로 판단합니다.

- 최신 개발 도구와 런타임이 구형 OS를 지원하지 않는 경우가 많습니다.
- 구형 OS는 보안 업데이트가 끝나 일반 사용자의 사용 비중이 매우 작습니다.
- 접근성 API(UI Automation 등)가 구형 OS에서는 제한적이거나 없습니다.

실제 필요 여부는 사용자 조사로 확인합니다.

## 6. 열린 질문

- 사용자가 가장 자주 쓰는 프로그램은 무엇인가요? (웹 브라우저, 한글/Word, 메신저, 은행/공공 사이트 등)
- 기존 화면 읽기 프로그램에서 가장 불편한 점은 무엇인가요?
- 한국어 음성은 어떤 TTS를 기본으로 할까요? (시스템 내장, 무료 오픈소스, 클라우드 등)
- 한컴오피스, 공공/금융 보안 프로그램 등 국내 환경에서 특히 중요한 프로그램의 접근성은 어떻게 확보할까요?
- 라이선스는 무엇으로 정할까요?

## 7. 사용자 조사용 질문 예시

- 지금 사용하는 화면 읽기 프로그램과 사용 기간
- 컴퓨터로 가장 자주 하는 일 3가지
- 가장 불편했던 상황과 원인
- 꼭 있었으면 하는 기능
- 가격이나 배포 방식에서 겪은 어려움
