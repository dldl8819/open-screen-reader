# Windows C# 프로토타입

[기술 스택 비교](../../docs/tech-comparison.md)의 검증 항목 P1, P2, P3을 확인하기 위한 프로토타입입니다.
포커스가 바뀌면 그 요소의 이름과 역할을 음성으로 읽고, 그 과정의 지연을 기록합니다.

이 코드는 측정이 끝나면 버려도 되는 코드입니다. 본 구현의 언어는 여기서 얻은 측정값을 보고 정합니다.

## 준비물

- Windows 10 또는 11
- .NET 10 SDK
- 한국어 SAPI 5 음성 (한국어 Windows에는 "Microsoft Heami Desktop"이 기본으로 들어 있습니다)

## 실행

이 폴더에서 실행합니다.

```
dotnet run -c Release
```

시작 안내 음성이 나온 뒤부터 포커스를 추적합니다. Ctrl+C를 누르면 지연 요약을 출력하고 끝납니다.

옵션은 `--` 뒤에 붙입니다. 예: `dotnet run -c Release -- --seconds 60`

| 옵션 | 설명 |
| --- | --- |
| `--list-voices` | 설치된 SAPI 5 음성 목록을 출력하고 끝냅니다. |
| `--voice <이름>` | 사용할 음성 이름. 생략하면 한국어 음성을 찾습니다. |
| `--rate <-10..10>` | 말하기 속도. 기본값은 0입니다. |
| `--seconds <초>` | 지정한 시간이 지나면 스스로 끝냅니다. |
| `--log <경로>` | 지연 기록 CSV 경로. 기본값은 `logs/latency-<시각>.csv`입니다. |

## 검증 항목과 코드

| 번호 | 검증 내용 | 파일 | 방식 |
| --- | --- | --- | --- |
| P1 | 포커스 변경 이벤트로 이름과 역할 읽기 | `FocusWatcher.cs` | UI Automation COM API(`IUIAutomation`)의 포커스 변경 이벤트. 이름과 역할은 캐시 요청으로 이벤트와 함께 받습니다. |
| P2 | 읽은 텍스트를 TTS로 출력 | `SpeechOutput.cs` | `System.Speech`를 통한 SAPI 5 음성. |
| P3 | 포커스 이동부터 음성 시작까지 지연 측정 | `LatencyLog.cs` | 구간별 시각을 `Stopwatch`로 재어 CSV에 남깁니다. |

새 포커스가 오면 이전 음성을 끊습니다. P4의 범위이지만, 끊지 않으면 앞 문장을 기다린 시간이 지연에 섞여 P3 측정이 무의미해지기 때문에 넣었습니다.

## 측정하는 구간

모든 구간은 **UIA 이벤트 처리기에 들어온 시각**을 0으로 두고 잽니다. 단위는 밀리초입니다.

| CSV 열 | 의미 |
| --- | --- |
| `properties_ms` | 이름과 역할을 다 읽은 시각 |
| `speak_requested_ms` | 이전 음성을 끊고 새 음성을 엔진에 넘긴 시각 |
| `speak_started_ms` | 엔진이 문장을 처리하기 시작한 시각 |
| `first_audio_ms` | 첫 낱말 경계 이벤트 시각. 소리가 나기 시작한 시각의 근삿값이며, P3의 주 지표입니다. |

값이 비어 있으면 그 단계에 가기 전에 다음 포커스가 와서 중단된 것입니다. `cancelled` 열이 1이면 끝까지 읽지 못한 문장입니다.

## 이 측정의 한계

- **키 입력부터 이벤트 수신까지는 재지 않습니다.** 사용자가 체감하는 지연은 여기서 잰 값보다 큽니다. 이 구간은 UIA와 대상 프로그램이 결정하므로 구현 언어와 무관하지만, 전체 목표치를 정하려면 필요합니다. 입력 후킹(P5)을 넣을 때 함께 측정합니다.
- **첫 소리 시각은 근삿값입니다.** 엔진이 알려 주는 낱말 경계 이벤트를 쓰며, 스피커에서 실제로 소리가 난 시각이 아닙니다. 정확히 재려면 출력 장치의 소리를 직접 녹음해 비교해야 합니다.
- **SAPI 5만 측정합니다.** Windows OneCore 음성은 아직 넣지 않았습니다.
- **같은 요소에 대한 중복 이벤트를 걸러 내지 않습니다.** 프로그램에 따라 같은 내용을 두 번 읽기 시작할 수 있습니다.
- **실행 직후 몇 건은 느립니다.** .NET이 코드를 처음 실행할 때 번역(JIT)하는 시간이 들어갑니다. 통계를 낼 때는 처음 몇 건을 빼고 봅니다.

## 검증 절차

1. `dotnet run -c Release`로 실행합니다.
2. 메모장, 파일 탐색기, 크롬에서 각각 Tab, 방향키, Alt+Tab으로 포커스를 20회 이상 옮깁니다.
3. 이름과 역할이 맞게 들리는지 확인합니다. 틀리거나 빠진 요소는 따로 적어 둡니다. (P1, P2)
4. Ctrl+C로 끝내고 지연 요약과 CSV를 확인합니다. (P3)
5. 프로그램별 중앙값과 95% 값을 `docs/tech-comparison.md`에 기록하고 목표치를 정합니다.

## 기록 파일에 대한 주의

CSV에는 포커스를 받은 화면 요소의 이름(창 제목, 파일 이름 등)이 그대로 들어갑니다. `logs/` 폴더는 Git에서 제외되어 있습니다. 측정 결과를 공유할 때는 이름 열을 지우고 올려 주세요.
